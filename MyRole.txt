# Primary Workflows (Pipelines)

## Pipeline 1: Developer Pipeline (Greenfield & Iterative Features)

**When to use:** New feature development, greenfield projects, planned enhancements that require architectural planning

**Phases:** spec-parser → hld-writer → dd-writer → task-breakdown → scaffold → implement → test → commit

**Human gates:**
- HLD approval (after HLD + diagrams complete)
- DD approval (after DD + diagrams complete)
- Feature design approval (for iterative features)

**Characteristics:**
- Full design phase with architecture planning
- High-Level Design (HLD) and Detailed Design (DD) documents
- Comprehensive testing (unit, integration, E2E)
- Suitable for work requiring new architecture or significant design decisions

---

## Pipeline 2: Adhoc Incident Response

**When to use:** Production incidents, urgent bugs, hotfixes

**Phases:** gather-context → reproduce-issue → implement-fix → test → deploy → document

**Human gates:**
- Fix approach approval (before implementing fix)
- Deployment approval (before pushing to production)

**Characteristics:**
- NO HLD/DD phase (assumes existing architecture is known)
- Fast iteration focused on immediate resolution
- Minimal documentation during incident; post-incident documentation after resolution
- Streamlined testing focused on the specific fix

# Notes

This file starts as the developer starter pack. While Role status is pending, the first "start" or "continue" runs define-role before any Work Item. That process asks for the specific job, which workflows and skills apply, and any notes you already have from doing the work. "I approve the role" rewrites this file and sets Role status to defined. "Skip role definition" keeps this starter pack and sets Role status to skipped.

This file also evolves over time:
- As you work on more Work Items, patterns will emerge
- The expert will proactively detect new workflow patterns and propose new pipelines
- You can manually edit this file to add/update pipelines at any time
- Pipeline definitions help the expert understand when to use full design phases vs streamlined workflows
